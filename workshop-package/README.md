# 90 分鐘工作坊｜從零到自己的網站上線

**講者手冊 v1.0**

給完全零基礎的學員：親手打出一個術後自我檢查網頁，推上 GitHub，用 Netlify 讓全世界打得開，
再學會網頁改壞時怎麼救回來。

- **對象**：完全沒寫過程式的醫護人員，10–20 人
- **師資**：講者一人，無助教
- **路線**：命令列完整路線（Git／GitHub CLI／Netlify CLI）
- **成品**：本 repo 正式版 `index.html`（994 行）的骨架簡化版，約 60 行

---

## 這份教案的核心設計前提

> **安裝軟體全部移到課前，當天第一分鐘就開始寫程式。**

命令列路線在 90 分鐘內是可行的，但只有在這個前提下成立。
`winget` 裝四套工具＋`gh auth login`＋`netlify login`，10–20 人在現場做，
以單一講者的救援能量，實測至少吃掉 40 分鐘，而且會有 2–3 人完全卡死。
把安裝留在當天，這場工作坊會失敗。

因此：

| 時段 | 內容 | 負責 |
|---|---|---|
| T-7 天 | 寄 [`00-prework.md`](00-prework.md)（**兩頁，唯一要學員讀的文件**）。附件是**整個資料夾打包成一個 zip**——`install.bat` 需要 `install.ps1` 在同一層 | 講者 |
| T-3 天 | 三行提醒信：帳號先開好、安裝場時間、已通過者免參加 | 講者 |
| T-2 天 | 收自檢截圖；**只對沒回的人**一對一問一句 | 講者 |
| T-1 天 | **開 30 分鐘安裝場** → 教案見 [`install-session.md`](install-session.md) | 講者 |
| T-1 晚 | 一對一處理沒過的人（15 分鐘／人） | 講者 |
| 當天早上 | 一行提醒：**記得帶手機** ＋ 講義網址 | 講者 |
| 當天 −30 分 | 教室開放，最後補救 | 講者 |
| 當天 0–90 分 | 本教案 | 全體 |

> **不要寫長信。** 學員只會讀一份東西，就是那兩頁的 `00-prework.md`。
> 其餘幾次聯絡各寫三行以內即可，寫多了沒人看，還會讓人以為這件事很麻煩。
> 寄出前記得取代 `00-prework.md` 裡的 `【截止日】`、`【安裝場時間】`、`【安裝場連結】`。

**兩條路要同時走**：一份讓有信心的人自己準備（[`00-prework.md`](00-prework.md)），
加一場你親自帶的安裝場（[`install-session.md`](install-session.md)）把卡住的人救回來。
只做前者，會有三到五個人默默放棄且不回報；只做後者，你會浪費時間陪已經會的人。

**沒有交自檢截圖的人，當天請坐在教室後排並直接使用追進度包**，不要拖住全班。

### 關於 `handout.html`：務必課前部署

這是學員當天唯一要開的網頁。**請在 T-2 天前自己把它部署到 Netlify**，然後把網址縮短、印成大張 QR code。

```powershell
# 在 docs/workshop/ 裡執行即可，不需要 build
netlify deploy --prod --dir=.
```

三個理由：

1. **不部署就沒有複製鈕可用。** 讓學員自己找檔案雙擊開，會有人開不起來、有人開到舊版。
2. 手機也能看。有人會用手機看步驟、筆電打字。
3. **它本身就是最好的開場示範**——你可以說「你們現在看的這個網頁，就是我用今天要教的方法放上去的。90 分鐘後你們每個人都會有一個。」

**設計上的關鍵取捨（不要自己改掉）**：
指令區塊有複製鈕，**HTML／JavaScript 程式碼區塊故意沒有**。
手打程式碼就是這堂課本身；給了鈕，他們會直接貼上，什麼都學不到。
真的打不完的人，走收合起來的逃生口——安全網存在，但不是預設路徑。

## 單一講者的四個控場機制

沒有助教，你不可能一個一個救。改成讓教室自己運轉：

**1. 紅綠牌**
每人桌上一張 A5 紙，一面綠一面紅。跟上＝綠色朝上，卡住＝紅色朝上。
你站在教室前方掃一眼就知道進度分布。紅牌超過三張就暫停全班，統一講解。

**2. 兩兩配對（buddy）**
進場報到時就配對，兩人並排坐。**規則：卡住先問旁邊的人，兩個人都不會才翻紅牌。**
這一條可以吸收掉七成的問題。

**3. 90 秒規則**
你對單一學員除錯**不超過 90 秒**。超過就說「先用追進度包跟上，下課我再看你的」，然後走開。
這是整場最重要的紀律。破戒一次，後面全部崩盤。

**4. 綠燈牆**
每個里程碑完成，學員把成功訊號貼到共用線上表單（或白板寫名字）。
你看數量決定要不要延長：**超過 8 成完成才往下走**。

### 00:00–00:04　開場：為什麼要學這個（4 分鐘）

**不要**在這裡講課程大綱、不要自我介紹超過 20 秒、不要講「什麼是 HTML」。
這 4 分鐘只做一件事：**讓他們想做**。

1. （90 秒）手機投影打開 <https://ntucc-breastca-rehab-screen.netlify.app>，當著他們的面操作一次。

   > 這是台大癌醫中心正在用的乳癌術後復健轉介篩選工具。
   > 它不是 App，沒有後端，就是**一個檔案**。
   > 今天下課前，你們每個人都會有一個自己的、任何人打得開的版本。

2. （60 秒）舉起實體的乳癌術後篩檢表 PDF，跟畫面並排。

   > 這一頁紙，跟那個網頁，做的是**同一件事**。
   > 差別只在一個要影印、要發、要收回來打字；另一個不用。

3. （60 秒）**先把最大的恐懼拆掉**（這段最重要，慢慢講）：

   > 我知道等一下要開的那個黑色視窗，是今天最讓人緊張的東西。
   > 先講三句話：
   > **第一，你不會弄壞電腦。** 今天所有指令都是安全的。
   > **第二，出現紅字是正常的。** 我自己每天都在看紅字。紅字不是你的錯，是電腦在跟你講話。
   > **第三，今天總共只會用到七個指令。** 不是七十個，是七個。卡片上都印好了。

4. （30 秒）宣布三條規則：紅綠牌、buddy 制、追進度包位置（指白板 QR code）。

### 00:04–00:15　第 0 段：終端機求生（11 分鐘）

> **這一段是為「連終端機都沒開過」的人設計的。**
> 全場最容易崩盤的地方不是寫程式，是**不知道自己在哪個資料夾**、
> 以及**用手打長指令打錯字**。這 11 分鐘把這兩件事永久解決。
>
> 搭配講義：[`terminal-card.md`](terminal-card.md)（終端機生存卡，當天發實體紙本）

#### 0a（2 分鐘）用滑鼠建資料夾——先用他們會的技能

全體用**滑鼠**在桌面按右鍵 → 新增 → 資料夾 → 命名 `my-first-page`。

> 講：這一步你們本來就會。今天所有事情都發生在這個資料夾裡面。

**為什麼要這樣做**：讓第一步 100% 成功。開場第一個動作絕對不能是打指令。

#### 0b（2 分鐘）在資料夾裡面開終端機——**永遠不要教 `cd`**

全體**雙擊進入** `my-first-page` 資料夾（裡面是空的），然後在**空白處按右鍵**：

| 系統 | 做法 |
|---|---|
| Windows 11 | 右鍵 → 「**在終端中開啟**」 |
| Windows 10 | **Shift + 右鍵** → 「在此處開啟 PowerShell 視窗」 |
| 都沒有 | 檔案總管上方**網址欄**，路徑刪掉打 `powershell` 按 Enter |

**講者要特別強調的一句話**：

> **不要從開始選單找 PowerShell。** 那樣打開會在錯誤的位置，你會迷路。
> 一定要「先用滑鼠走到資料夾，再在裡面右鍵開」。
> 這樣你今天**完全不需要學 `cd` 這個指令**。

> ⚠️ **講者課前務必自己確認一次**你的 Windows 版本右鍵選單長什麼樣，
> 並準備兩張截圖（Win10／Win11）投影。教室裡兩種版本都會有。

#### 0c（2 分鐘）認識這個黑窗

投影自己的畫面，用滑鼠圈出提示字元：

```
PS C:\Users\你的名字\Desktop\my-first-page>
   └────────────┬──────────────────────┘  └ 游標在這裡等你打字
                │
        這一串就是「你現在在哪個資料夾」
```

> 講：這個視窗只有兩個部分。左邊那串是**你在哪**，游標後面是**你要打什麼**。
> 以後只要覺得怪，第一件事就是**看左邊那串對不對**。

請全體確認左邊那串結尾是 `my-first-page`。**不對的人翻紅牌。**
（這是全場第一個檢查點，務必等到全綠再往下。）

#### 0d（3 分鐘）三個安全指令：Enter、↑、右鍵貼上

**第一個指令**——請他們手打（故意讓他們體驗打字＋Enter）：

```powershell
echo 我今天要做一個網站
```

> 講：按 Enter。……電腦把你的話回給你了。
> **你剛剛下了人生第一個指令。** 就這樣，沒有更難的。
> 記住：**打完要按 Enter，不按 Enter 什麼都不會發生。**

**第二個動作**——教 ↑：

> 現在按一下鍵盤上的**上方向鍵**。……看到了嗎？剛剛那行又回來了。
> 這是今天最常用的一招：**打錯字不要重打，按 ↑ 叫回來改一個字就好。**

**第三個動作**——教右鍵貼上（**這招價值最高**）：

講者把下面這行放在白板／共用文件，請學員**複製**，然後在黑窗裡貼上：

```powershell
git --version
```

> 講：貼上**不是按 Ctrl+V，是按滑鼠右鍵**。試試看。
> ……出現版本號碼了，代表 Git 裝好了。
>
> 這招今天會救你很多次。**長的指令一律用複製＋右鍵貼上，不要用手打。**
> 手打會打錯，打錯就要花時間找，找不到就落後。

**第四個指令**——確認 GitHub 登入（同樣用貼上）：

```powershell
gh auth status
```

> 先預告：**這個會吐一堆字，有些可能是紅色或黃色的，那是正常的。**
> 你只要找一件事：**畫面上有沒有出現你的 GitHub 帳號名稱。** 有就對了。

#### 0e（2 分鐘）紅字宣言 ＋ 卡住流程

指著生存卡最後一段，全班一起看：

> 從現在到下課，你會看到很多看不懂的字。**不要一個一個看懂。** 只找三樣：
> 1. 有沒有出現**你的名字或你的網址** → 通常代表成功
> 2. 有沒有 `error` 或 `not recognized` → 有的話**整段截圖**，先問你的 buddy
> 3. 有沒有叫你**做某件事** → 照著做
>
> 還有兩個一定會遇到的：
> **游標在閃就是在做事**，有些指令要等 10–30 秒，不要一直按 Enter。
> **打密碼時畫面不會動**，那是安全設計，照打完按 Enter。

**成功訊號（本段）**：全班左邊提示字元都是 `my-first-page`，且都成功用右鍵貼上過一次指令。

**常見卡關**

| 症狀 | 一句話解法 |
|---|---|
| 右鍵沒有「在終端中開啟」 | 用 Shift+右鍵，或網址欄打 `powershell` |
| 左邊那串不是 my-first-page | 關掉視窗，重新用滑鼠進資料夾再右鍵開 |
| 右鍵貼上沒反應 | 改按 Ctrl+V；或右鍵一次就好不要連按 |
| 中文 `echo` 出現亂碼 | 不影響後面任何步驟，跳過即可 |
| `git --version` 說找不到 | 課前沒裝成功 → 立刻併到 buddy 那台，兩人一組 |

**卡關**：`git --version` 失敗的人 → **立刻**配到已通過者旁邊共用一台筆電，兩人一組完成全場。
**不要當場修電腦**，那會吃掉你整場的時間。

### 00:15–00:25　里程碑 1：本機第一個網頁（10 分鐘）

> 資料夾與終端機在第 0 段已經就位，這裡**不需要 `cd`、不需要 `mkdir`**。
> 學員的黑窗已經在 `my-first-page` 裡面了。

**學員做**

```powershell
notepad index.html
```

跳出「找不到檔案，是否建立新檔？」→ 按**是**。

> 講：記事本就是你的程式編輯器。**寫程式用的就是記事本，沒有更神祕的工具。**

然後**講者逐行念、學員逐行打**（不要投影完整檔案讓他們自己抄，會有人跳行）：

```html
<!DOCTYPE html>
<html lang="zh-Hant">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>術後自我檢查</title>
  <style>
    body { font-family: sans-serif; max-width: 480px; margin: 40px auto; padding: 0 16px; }
  </style>
</head>
<body>

  <h1>術後自我檢查</h1>
  <p>這是我做的第一個網頁。</p>

</body>
</html>
```

存檔（Ctrl+S），然後：

```powershell
start index.html
```

**成功訊號**：瀏覽器開啟，分頁標題是「術後自我檢查」，畫面上有大標題和一行字。

**講者說什麼**

> `<h1>` 到 `</h1>` 中間的東西，就是大標題。前面那個是「開始」，後面加斜線那個是「結束」。
> HTML 全部就是這個規則，沒有別的。
> 那個 `<style>` 區塊是化妝，把它刪掉網頁還是活的，只是變醜。

**這段的教學重點**：標籤成對出現。其他都先不解釋。

**常見卡關**

| 症狀 | 一句話解法 |
|---|---|
| 記事本存成 `index.html.txt` | 存檔時「存檔類型」選**所有檔案** |
| 中文變亂碼 | 記事本右下角編碼改 **UTF-8**，重存 |
| 打太慢 | 給追進度包 `step1-hello.html`，複製貼上 |
| `mkdir` 說已存在 | 直接 `cd my-first-page` |

> **投影片上永遠顯示當前這一段的完整程式碼**，不要切走。慢的人靠這個追。

### 00:25–00:36　里程碑 2：推上 GitHub（11 分鐘）

**學員做**（確認自己在 `my-first-page` 資料夾內）

```powershell
git init
git add .
git commit -m "我的第一個網頁"
gh repo create my-first-page --public --source=. --push
gh repo view --web
```

**成功訊號**：瀏覽器自動開啟 GitHub，上面有自己的 `index.html`。

**講者說什麼**（這段的比喻決定他們往後三年會不會用 Git，講慢一點）

> - `git init`：跟電腦說「這個資料夾開始要記錄版本了」。只做一次。
> - `git add .`：把改動的東西**放進紙箱**。（`.` 是「全部」）
> - `git commit -m "..."`：**封箱、貼標籤**。這就是一個存檔點，永遠可以回來。
> - `gh repo create ... --push`：把箱子**寄到 GitHub**。
>
> 為什麼要這麼麻煩？因為有了存檔點，你才敢亂改。
> 這是 Git 真正的價值——不是備份，是**讓你敢動手**。

**常見卡關**

| 訊息 | 一句話解法 |
|---|---|
| `Author identity unknown` | 補跑課前那兩行 `git config --global` |
| `not a git repository` | 走錯資料夾，`cd` 回去 |
| `name already exists` | 改名字：`gh repo create my-first-page-2 ...` |
| `gh: could not authenticate` | 重跑 `gh auth login` |
| 卡在編輯器打不出來 | 你少了 `-m "訊息"`，按 `Esc` 再打 `:q!` Enter 退出，重來 |

> `git commit` 沒帶 `-m` 會掉進 Vim，零基礎會完全嚇壞。**這一點請事先提醒。**

### 00:50–01:09　里程碑 4：變成真的篩檢工具（19 分鐘）

分三小段，**每段改完立刻回瀏覽器按 Ctrl+F5 看效果**。

#### 4a（6 分鐘）加三個是非題

在 `<style>` 裡加一行：

```css
    label { display: block; margin: 12px 0; }
```

在 `<p>這是我做的第一個網頁。</p>` 下面加：

```html
  <h2>過去一週，你有下列情形嗎？（有就打勾）</h2>
  <label><input type="checkbox" class="q"> 手臂舉不高，梳頭或晾衣服有困難</label>
  <label><input type="checkbox" class="q"> 手臂或腋下緊繃、疼痛</label>
  <label><input type="checkbox" class="q"> 手或手臂腫脹</label>
```

> 講：這三行幾乎一模一樣，只有中文不同。**程式就是這樣，重複的部分用複製貼上。**
> `class="q"` 是給它們一個共同的名字，等一下 JavaScript 要靠這個一次抓到三個。

參考答案：[`steps/step2-questions.html`](steps/step2-questions.html)

#### 4b（7 分鐘）加疲憊度滑桿——第一次寫 JavaScript

`<style>` 裡加：

```css
    #slider { width: 100%; }
```

三題下面加：

```html
  <h2>疲憊程度</h2>
  <input type="range" id="slider" min="0" max="10" value="0">
  <p>目前分數：<b id="score">0</b> / 10</p>
```

`</body>` **前面**加：

```html
  <script>
    var slider = document.getElementById('slider');
    var score  = document.getElementById('score');

    slider.oninput = function () {
      score.textContent = slider.value;
    };
  </script>
```

**成功訊號**：拉滑桿，數字即時跟著變。

> 講：`getElementById` ＝「幫我找到叫這個名字的東西」。
> `oninput = function () {...}` ＝「當它被拉動的時候，做這件事」。
> HTML 是長相，CSS 是化妝，**JavaScript 是行為**。今天你已經三個都碰過了。

參考答案：[`steps/step3-slider.html`](steps/step3-slider.html)

#### 4c（6 分鐘）加判讀邏輯

`<style>` 裡加：

```css
    button  { font-size: 16px; padding: 10px 20px; margin-top: 8px; }
    #result { margin-top: 16px; padding: 12px; border-radius: 8px; }
    .warn   { background: #ffe6e6; border: 1px solid #ff9a9a; }
    .ok     { background: #e6f7e9; border: 1px solid #8fd39c; }
```

滑桿那段下面加：

```html
  <button id="check">看結果</button>
  <div id="result"></div>
```

`<script>` 裡，在最後一個 `};` 後面加：

```javascript
    document.getElementById('check').onclick = function () {
      var hasDifficulty = document.querySelectorAll('.q:checked').length > 0;
      var isTired       = Number(slider.value) > 4;
      var box           = document.getElementById('result');

      if (hasDifficulty || isTired) {
        box.className   = 'warn';
        box.textContent = '建議預約復健科門診，由醫療人員進一步評估。';
      } else {
        box.className   = 'ok';
        box.textContent = '目前狀況良好，請維持日常伸展與活動。';
      }
    };
```

**成功訊號**：把滑桿拉到 7，按「看結果」，出現紅底建議轉介。三題都不勾且滑桿 0，出現綠底。

**這是全場最重要的一段話**：

> 看這一行：`if (hasDifficulty || isTired)`。
> `||` 唸做「或」。**任一項活動困難，或疲憊分數大於 4，就建議轉介復健科。**
>
> 這條規則不是我編的，是從乳癌術後篩檢表的臨床準則來的：
> 「若術後六週或放療後仍有活動困難，或疲憊量尺 > 4，請預約復健科門診。」
>
> 也就是說——**你剛剛做的，是把一條臨床判讀規則，寫成了電腦看得懂的樣子。**
> 這就是你們這個職業寫程式最有價值的地方：規則在你們腦袋裡，別人沒有。

### 01:17–01:24　里程碑 6：改壞了怎麼救（7 分鐘）

**故意破壞。** 這一段學員通常最放鬆也記最牢。

1. 打開 `index.html`，**把整個 `<script>` 到 `</script>` 刪掉**，存檔。
2. 瀏覽器 Ctrl+F5 → 滑桿不動了，按鈕沒反應。**壞掉了。**
3. 看看發生什麼事：

   ```powershell
   git status
   ```

   > 講：紅色的 `modified: index.html` ＝ Git 知道你動了這個檔案，而且還沒存檔點。

4. 救回來：

   ```powershell
   git restore .
   ```

5. 瀏覽器 Ctrl+F5 → **全部回來了。**

**成功訊號**：功能復原。

接著只講不做（投影 `cheatsheet.md` 背面）：

```powershell
git log --oneline      # 看所有存檔點
git revert a1b2c3d     # 已經 push 上去才發現壞了，做一個反向存檔點
git push
```

**講者說什麼**

> 記住兩句話就好：
> - **還沒 commit 就改壞** → `git restore .`
> - **已經 push 才發現壞** → `git log --oneline` 找代號，`git revert` 那個代號，再 push。
>
> 這就是為什麼前面要一直 commit。
> **存檔點的價值，是讓你有膽子亂改。**
