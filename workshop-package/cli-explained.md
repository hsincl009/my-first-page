# 這些東西到底是什麼？

**給完全沒接觸過的人**：命令列是什麼、指令怎麼讀、我們裝的四個工具各自在做什麼。

> 這份是**理解用**的，不是操作用的。
> 想知道「手要怎麼動」看 [終端機生存卡](terminal-card.md)；想知道「指令怎麼打」看 [指令小抄](cheatsheet.md)。
> **這份看不完不影響上課。** 但看完你會知道自己在做什麼，而不是照著抄。

---

## 一、命令列（CLI）是什麼

### 兩種跟電腦說話的方式

你現在用電腦的方式叫 **GUI**（圖形介面）：看到圖示，用滑鼠點。

另一種叫 **CLI**（Command Line Interface，命令列介面）：**打字告訴電腦要做什麼**。

它有很多名字，看到哪個都是同一件事：**命令列／終端機／PowerShell／黑窗／console**。

### 拿點餐來比

| | GUI（滑鼠） | CLI（打字） |
|---|---|---|
| 像什麼 | 看**圖片菜單**用手指點 | 直接跟廚師說「牛肉麵，大碗，不要香菜」 |
| 好處 | 不用記，看得到 | **精確**、**快**、**可以一次交代很多條件** |
| 壞處 | 複雜的需求點不出來 | **你要先知道菜名** |

「不要香菜」這種要求，圖片菜單上通常沒有按鈕可以點。CLI 就是那個「可以講細節」的方式。

### 為什麼今天非用它不可

三個誠實的理由：

1. **有些工具根本沒有滑鼠介面。** Git 本身就沒有。
2. **它可以被寫下來。** 「按這裡→再按這裡→勾那個」很難傳達；`git push` 三個字貼給你就能重現。這也是為什麼今天的講義能給你複製鈕。
3. **它不會因為改版而失效。** 軟體換版面，按鈕位置就變了；指令十年沒變。

> **重要**：CLI 不是「比較高級的用法」，只是**另一種介面**。
> 它看起來嚇人只因為沒有按鈕可以摸索 —— 一片黑，你不知道能做什麼。
> 而這就是為什麼今天只教你**七個指令**，並且全部印在卡片上。

### 你不會弄壞電腦

一個常見的恐懼，先講清楚：

- 今天用到的指令**全部都是安全的**。最壞的情況是「它不做事，然後印一行紅字」。
- **紅字不是壞掉**，是電腦在跟你講「我不懂」或「你少了什麼」。
- 真正危險的指令（刪整顆硬碟那種）你今天完全碰不到，而且它們長得跟今天的指令很不一樣。

## 二、指令長什麼樣子（這一節最有用）

看懂**一個**指令的結構，你就看得懂**全部**指令。

```
git   commit   -m   "..."
 ^      ^       ^     ^
 1      2       3     4
```

| | 名稱 | 白話 | 這個例子 |
|---|---|---|---|
| 1 | **程式名** | 找誰做 | `git`：找 Git 這個工具 |
| 2 | **子指令** | 做什麼（動詞） | `commit`：做一個存檔點 |
| 3 | **選項**（flag） | 附加條件 | `-m`：我要順便寫一段說明 |
| 4 | **值** | 選項要用的資料 | `"我的第一個網頁"`：說明的內容 |

**這就是全部了。** 每一個指令都是這四種東西的組合，有的少一兩樣。

### 五條讀指令的規則

**1. 用空白分隔。** 所以**內容裡有空白時要用引號包起來**，不然電腦會以為那是兩個東西。

```powershell
git commit -m "我的第一個網頁"     # 對：引號讓它知道這整段是一個東西
git commit -m 我的 第一個 網頁      # 錯：它會以為你交代了三件事
```

**2. 一個橫線是縮寫，兩個橫線是全名。** 通常是同一件事的兩種寫法。

```powershell
git commit -m "訊息"              # 短的
git commit --message "訊息"       # 長的，完全一樣
```

短的好打，長的好懂。文件上常寫長的，實際用常打短的。

**3. 一個點 `.` 代表「這個資料夾」，也常常代表「全部」。**

```powershell
git add .          # 把這個資料夾裡全部的改動放進紙箱
git restore .      # 把全部改動丟掉
```

**4. 有些選項不需要值**，它本身就是一個「開關」。

```powershell
gh repo create my-page --public    # --public 就是「設成公開」，後面不用再接東西
```

**5. 卡住的時候，加 `--help`。** 幾乎每個工具都吃這一招。

```powershell
git --help
git commit --help
netlify --help
```

（`--help` 會吐出一大堆英文，看不懂沒關係。你只要知道**這招存在**，以後想查的時候用得上。）

### 什麼是「子指令」

有些工具功能很多，就把功能分組，用「第二個字」來選。這第二個字叫子指令。

```
git   init      建立
git   add       放進紙箱
git   commit    封箱
git   push      寄出
git   status    現在怎樣？
git   restore   還原
```

同一個 `git`，六件不同的事。**你可以把它想成「git 這個部門，底下有六個窗口」。**

## 三、我們裝的四個工具，各自在做什麼

安裝程式裝了四個東西。很多人裝完完全不知道自己裝了什麼，這裡一次講清楚。

| 工具 | 一句話 | 在哪裡 | 今天你會直接用嗎 |
|---|---|---|---|
| **Git** | 幫你的檔案做存檔點 | **你的電腦裡** | **會**，用最多 |
| **GitHub CLI**（`gh`） | 讓你用打字操作 GitHub 網站 | 你的電腦裡 | 會，用一次 |
| **Node.js ＋ npm** | 「能跑 JavaScript 的引擎」和它的 App Store | 你的電腦裡 | **不會直接用** |
| **netlify-cli** | 把你的資料夾送上網站 | 你的電腦裡 | 會，用一次 |

### Git：像遊戲存檔

Git 做一件事：**在你改壞東西之前，先存檔**。

打遊戲的時候，你會在打大魔王前先存檔，因為死了可以重來。Git 就是給檔案用的存檔功能。

- 做一個存檔點 → `git commit`
- 現在跟上次存檔差在哪 → `git status`
- 改壞了，回到上次存檔 → `git restore .`

**Git 的價值不是備份，是讓你敢亂改。** 這是今天最重要的一句話。

### Git ≠ GitHub（最常見的誤會）

名字很像，但**是兩個完全不同的東西**：

| | Git | GitHub |
|---|---|---|
| 它是什麼 | 一個**程式**，裝在你電腦裡 | 一個**網站** |
| 在哪 | 你的電腦，離線也能用 | 網路上 |
| 做什麼 | 做存檔點 | 幫你把存檔**放到雲端**，還能給別人看 |
| 誰做的 | 2005 年，Linux 那群人 | 一間公司（現在屬於微軟）|

比喻：**Git 是相機，GitHub 是雲端相簿。** 你可以只用相機不上傳，但不能沒有相機就有照片。

還有其他放 Git 存檔的網站（GitLab、Bitbucket），我們選 GitHub 只是因為它最大、跟 Netlify 接最順。

### GitHub CLI（`gh`）：GitHub 網站的打字遙控器

GitHub 是網站，本來要用滑鼠操作。`gh` 讓你**在黑窗裡直接叫 GitHub 做事**，不用切到瀏覽器。

今天只用它一次，但那一次省掉大約六個滑鼠步驟：

```powershell
gh repo create my-first-page --public --source=. --push
```

這一行等於在 GitHub 網站上：登入 → 按 New repository → 打名字 → 選 Public → 按 Create → 複製網址 → 回黑窗設定 → 上傳。

### Node.js 和 npm：為什麼我要寫網頁卻得裝這個？

**這是最多人卡住的疑問，答案很簡單：你不是要用它，只是要用它來裝別的東西。**

- **Node.js** 是一個「能在你電腦上跑 JavaScript 的引擎」。
  （JavaScript 本來只在瀏覽器裡跑，Node 讓它也能在電腦上跑。）
- **npm** 是 Node 附帶的**軟體商店**（像手機的 App Store）。

而 `netlify-cli` 這個工具，剛好是用 JavaScript 寫的、放在 npm 這個商店裡。所以：

```
要用 netlify 指令  →  它住在 npm 商店裡  →  npm 是 Node 附的  →  所以要先裝 Node
```

**就這樣。** 今天你不會打任何一行 Node 或 npm 的指令，它們只是「為了裝 netlify 而存在的前置條件」。

> 順便解釋你在安裝畫面看到的那行：
> ```powershell
> npm install -g netlify-cli
> ```
> `npm` 商店 → `install` 安裝 → `-g` 是 global，**裝到整台電腦都能用**（不加就只有當前資料夾能用）→ `netlify-cli` 要裝的東西的名字。

### netlify-cli：把資料夾送上網的搬家工人

**Netlify** 是一家提供免費網站空間的公司 —— 你可以想成**出租伺服器的房東**。你把資料夾交給他，他給你一個網址。

`netlify-cli` 是在你電腦上的那個工具，負責把資料夾**送過去**。

```powershell
netlify init      # 第一次：跟房東簽約，把你的 GitHub 倉庫接起來
```

接起來之後就自動了：**你 push 到 GitHub，Netlify 就自己去抓新版本，重新產生網站。** 你不用再管它。

## 四、東西到底跑到哪裡去了

這張圖是今天最重要的心智模型。**搞懂它，你就懂整個流程。**

```
        你的電腦                              網路上
   ---------------------
   |   my-first-page   |
   |     index.html    |   <-- 你在這裡打字
   |                   |
   |   [ Git 在管理 ]  |   <-- git commit 在這裡做存檔點
   ---------------------
             |
             |   git push
             v
   ---------------------
   |      GitHub       |   <-- 你的程式碼倉庫（雲端備份 + 歷史紀錄）
   ---------------------
             |
             |   Netlify 自動偵測到有新版本，自己去抓
             v
   ---------------------
   |      Netlify      |   <-- 把你的資料夾變成一個真的網站
   ---------------------
             |
             v
     https://xxx.netlify.app     <-- 任何人、任何手機都打得開
```

三個地方，各管一件事：

| 地方 | 負責 | 壞掉的話 |
|---|---|---|
| **你的電腦** | 你動手改東西的地方 | 用 `git restore .` 救 |
| **GitHub** | 保存歷史、每一個存檔點 | 用 `git revert` 救 |
| **Netlify** | 對外開放的網站 | 修好前面兩個，它會自動跟上 |

**「部署」（deploy）這個詞就是指「把東西送到最下面那一層，讓外面的人看得到」。** 沒有更神祕的意思。

## 五、今天七個指令，逐一拆解

| 指令 | 拆解 | 白話 |
|---|---|---|
| `notepad index.html` | 程式名＋檔名 | 用記事本打開這個檔（不存在就問你要不要建） |
| `start index.html` | 程式名＋檔名 | 用預設程式（瀏覽器）打開這個檔 |
| `git init` | git＋子指令 | 跟 Git 說「這個資料夾開始要管版本了」。**只做一次** |
| `git add .` | git＋子指令＋`.` | 把這個資料夾**全部**的改動放進紙箱 |
| `git commit -m "訊息"` | git＋子指令＋選項＋值 | 封箱、貼標籤。**這就是一個存檔點** |
| `git push` | git＋子指令 | 把箱子寄到 GitHub |
| `git status` | git＋子指令 | 我現在有哪些東西還沒存檔？ |
| `git restore .` | git＋子指令＋`.` | 把**全部**還沒存檔的改動丟掉，回到上一個存檔點 |

以及各用一次的兩個：

**`gh repo create my-first-page --public --source=. --push`**

| 部分 | 意思 |
|---|---|
| `gh` | 找 GitHub CLI |
| `repo create` | 建立一個新倉庫（這裡子指令有兩層） |
| `my-first-page` | 倉庫的名字 |
| `--public` | 設成公開（開關，不用接值） |
| `--source=.` | 內容來源是「這個資料夾」 |
| `--push` | 建好之後順便上傳（開關） |

**`netlify init`** — 第一次跟 Netlify 接線。它會問你一連串問題，照講義的表回答就好。

## 六、常見疑問

**Q：為什麼指令成功的時候什麼都不顯示？**
A：這是 CLI 的傳統：**沒消息就是好消息**。它只在「有話要說」或「出問題」時才印字。
`git config` 設定成功就是一片安靜，那是對的。

**Q：紅字是不是代表我做錯了？**
A：不一定。有些工具連正常訊息都用紅色或黃色印（`gh auth status` 就是）。
**先找關鍵字**：有你的名字或網址 → 通常成功；有 `error`、`not recognized`、`failed` → 才是真的有問題。

**Q：我打錯字了，會不會出事？**
A：不會。電腦看不懂就直接回你一句「這是什麼」然後什麼都不做。
**按 `↑` 把指令叫回來，改掉錯的字，再 Enter。**

**Q：為什麼不能全部用滑鼠做完？**
A：有些可以（見主教案的純瀏覽器路線）。但 Git 本身沒有官方滑鼠介面，
而且用打字你才能**把步驟複製給別人**——這正是今天的講義能給你複製鈕的原因。

**Q：什麼是 repository？**
A：中文常叫「倉庫」或「儲存庫」，簡稱 **repo**。就是「**一個被 Git 管著的資料夾**」。
你的 `my-first-page` 跑完 `git init` 之後，它就是一個 repo 了。

**Q：`-g` 是什麼？**
A：global，**裝到整台電腦都能用**。不加 `-g` 就只有當前那個資料夾能用。
安裝 `netlify-cli` 這種「到處都想用的工具」就要加。

**Q：我需要記住這些指令嗎？**
A：**不用。** 沒有人在記。大家都是查小抄、翻舊紀錄、按 `↑` 找歷史。
真正需要記住的只有三個字：`add`、`commit`、`push`。

**Q：這些工具要錢嗎？**
A：Git、Node、gh、netlify-cli 全部免費開源。GitHub 公開倉庫免費。
Netlify 有免費方案，今天做的規模遠遠用不完。

## 七、如果只能記三件事

1. **CLI 只是另一種介面**，不是比較高級的用法。它看起來嚇人只因為沒有按鈕可以摸索。
2. **每個指令都是「程式名＋子指令＋選項＋值」。** 看懂這個結構，就看得懂全部指令。
3. **你的電腦 → GitHub → Netlify**，三個地方各管一件事。`push` 一次，後面自動跟上。
