# 安裝場（T-1）｜講者教案

**30 分鐘，線上分享畫面，10–20 人，講者一人**

> 這份是**給講者看的**。學員看的是 [`00-prework.md`](00-prework.md)。
>
> **唯一目標**：散會時每個人都跑出 `check.bat` 的「**全部通過**」。
> 不寫任何程式、不碰 HTML、不提 Git 指令。今天只做一件事：**把工具裝好、把帳號登入**。

---

## 為什麼一定要有這一場

正課 90 分鐘從第一分鐘就寫程式，前提是工具都好了。而「只寄一份文件叫大家自己裝」對零基礎會有三到五個人卡死 —— 他們不會回報，會直接放棄，然後正課當天坐在那裡什麼都做不了。

這 30 分鐘就是把那三到五個人救回來。

**兩條路同時走：**

| | 對象 | 材料 |
|---|---|---|
| 自己準備 | 有信心的人，先做完就不用來 | [`00-prework.md`](00-prework.md) ＋ [`terminal-card.md`](terminal-card.md) |
| 帶領安裝 | 沒信心、或自己做卡住的人 | 這一場 |

**宣布方式**：「已經跑出全部通過並截圖給我的人，這場可以不用來。其他人強烈建議參加。」

這樣會來的正好是需要幫助的人 —— 20 人可能只來 8 個，你救得完。

---

## 三天前要先做的事

**T-3 天寄一封三行的提醒信就好**，不需要範本，寫這三點：

1. 還沒開 GitHub／Netlify 帳號的請先開 —— **註冊要等 email 驗證碼，現場等會拖到全班**
2. 安裝場時間與連結
3. **已回傳「全部通過」截圖的人可以不用來**（讓出席的正好是需要幫助的人）

課前準備的完整內容在 [`00-prework.md`](00-prework.md)（兩頁），T-7 就已經寄出去了，這裡不用重複。

**帳號必須在安裝場之前開好。** 註冊流程有 email 驗證、雙重驗證，現場等會浪費全場時間。安裝場開場只花 3 分鐘處理漏網的人。

**講者自己要先做的**：

- [ ] 拿一台**乾淨的機器**（或新使用者帳號）完整跑一次 `install.bat`，確認能成功
- [ ] 拍好 **Windows 10 與 Windows 11 的右鍵選單截圖**各一張（教室裡兩種都會有）
- [ ] 確認會議軟體的**錄影**功能可用（沒來的人要看回放）
- [ ] 準備一個共用文件／聊天室，用來貼可複製的指令
- [ ] 開一份簡單的回報表單（姓名／截圖／卡在哪一步）

### 00:00–00:03　開場＋帳號漏網補救

**開場只講三句：**

> 今天 30 分鐘不寫任何程式，只把工具裝好。
> 散會的標準很明確：你的畫面上出現「**全部通過**」四個字。
> 過程中一定會有人卡住，那是正常的 —— 卡住就在聊天室貼截圖，我一個一個處理。

**然後點名確認兩件事**（請大家在聊天室打「有」或「沒有」）：

1. GitHub 帳號有了嗎？
2. Netlify 帳號有了嗎？（而且是用 GitHub 登入的？）

沒有的人 → 貼註冊連結，請他們現在開，**但不要全班等他們**。直接往下走，他們晚幾分鐘趕上。

---

### 00:03–00:06　先讓安裝跑起來

**這一段的順序很重要：先按下去，再解釋。** 安裝要跑 5–15 分鐘，越早開始越好。

請大家：

1. 打開解壓縮後的資料夾
2. **雙擊 `install.bat`**（副檔名是 `.bat` 那個）
3. 跳出「是否允許此應用程式變更您的裝置」→ 按 **【是】**
4. 畫面開始跑很多字 → **不要關掉，放著讓它跑**

**講者要主動預告三個狀況**（不預告的話，這三個各會有人舉手）：

| 狀況 | 你要說的話 |
|---|---|
| 雙擊後打開記事本 | 「你點到 `.ps1` 了。回去點 `.bat` 那一個。」 |
| 一閃就關掉 | 「改成在 `install.bat` 上按右鍵 → 以系統管理員身分執行。」 |
| 按不到【是】、或按了沒反應 | 「你的電腦被公司政策擋住了。先在聊天室告訴我，我等一下單獨處理你。」 |

**過關訊號**：請大家在聊天室打「跑了」。

### 00:06–00:14　趁安裝在跑，講終端機是什麼

> **這 8 分鐘是這場的核心價值。** 安裝在背景跑，本來是純等待時間；
> 拿來講終端機，等於白賺 8 分鐘，而且他們接下來馬上就要用到。
>
> 搭配講義：[`terminal-card.md`](terminal-card.md)。請大家把它印出來或開在旁邊。

分享你的畫面，打開一個黑窗，一邊示範一邊講：

**1. 這是什麼（1 分鐘）**

> 一個只能用打字操作的視窗。你平常用滑鼠雙擊資料夾、拖檔案 —— 做的是同一件事。
> 它只是換成打字告訴電腦要做什麼。**沒有比較高深，只是沒有按鈕。**
> 它有很多名字：終端機、命令列、PowerShell、黑窗。看到哪個都一樣。

**2. 你不會弄壞電腦（1 分鐘，慢慢講）**

> 這是今天最重要的一句話。
> **你不會弄壞電腦。錯誤訊息不是你的錯。** 紅色的字只是電腦在跟你講話。
> 我自己每天都在看紅字。會出錯是這一行的日常，不是你笨。

**3. 提示字元：左邊那串就是「你在哪」（2 分鐘）**

在自己畫面上圈出來：

```
PS C:\Users\你的名字\Desktop\my-first-page>
   └───────────────┬──────────────────┘  └ 游標在這裡等你打字
                   │
           這一串就是「你現在在哪個資料夾」
```

> 這個視窗只有兩個部分：左邊是**你在哪**，游標後面是**你要打什麼**。
> 以後只要覺得怪，第一件事就是**看左邊那串對不對**。

**4. 四個操作（3 分鐘，每個都示範一次）**

| 操作 | 講者示範什麼 |
|---|---|
| <kbd>Enter</kbd> | 打 `echo hello` 給他們看：不按 Enter 什麼都不會發生 |
| <kbd>↑</kbd> | 按上鍵把剛剛那行叫回來，改一個字再 Enter |
| **右鍵貼上** | 從共用文件複製一行，在黑窗按**右鍵** —— 不是 Ctrl+V |
| <kbd>Ctrl</kbd>+<kbd>C</kbd> | 中斷。「跑到一半不想跑了就按這個，也是安全的。」 |

**5. 兩個一定會遇到的誤會（1 分鐘）**

> **游標在閃就是在做事。** 有些指令要等 10–30 秒，不要一直按 Enter。
> **打密碼時畫面不會動。** 那是安全設計，不是沒吃到你的字，照打完按 Enter。

**這時候回頭看安裝**：多數人應該跑完了，畫面上會出現「還有三件事要自己做」。

**巡場**：問「誰的畫面已經停下來、出現『軟體安裝結束』了？」
還在跑的人不要催，讓他們繼續；先跑完的人往下走 —— **這個錯開是刻意的**。

#### 安裝跑得比 8 分鐘久？用這個填空檔

安裝時間差異很大（網路快慢、有沒有裝過），可能 5 分鐘也可能 15 分鐘。
**多出來的空檔用這個填**，內容出自 [`cli-explained.md`](cli-explained.md)：

> **「你剛剛在裝什麼？」**（可講 2–6 分鐘，隨時能停）
>
> **一、四個工具各自在做什麼**（投影這張表）
>
> | 工具 | 一句話 | 今天會直接用？ |
> |---|---|---|
> | **Git** | 幫檔案**做存檔點**，像遊戲存檔。在你電腦裡 | **會**，用最多 |
> | **gh** | GitHub 網站的**打字遙控器** | 會，用一次 |
> | **Node.js ＋ npm** | 「能跑 JavaScript 的引擎」和它的 **App Store** | **不會直接用** |
> | **netlify-cli** | 把資料夾**送上網**的搬家工人 | 會，用一次 |
>
> **二、Git 不等於 GitHub**（最常見的誤會，一定要講）
>
> > **Git 是相機**——一個程式，裝在你電腦裡，離線也能用。
> > **GitHub 是雲端相簿**——一個網站，幫你把存檔放到網路上。
> > 你可以只用相機不上傳，但不能沒有相機就有照片。
>
> **三、「我要寫網頁，為什麼要裝 Node.js？」**（他們一定會問，先講掉）
>
> > 因為你不是要**用**它，只是要**用它來裝別的東西**：
> > 要用 `netlify` 指令 → 它住在 npm 這個商店裡 → npm 是 Node 附帶的 → 所以要先裝 Node。
> > **今天你不會打任何一行 Node 或 npm 指令。**
>
> **四、如果還有時間：指令的四個部分**
>
> ```
> git   commit   -m   "..."
>  ^      ^       ^     ^
>  1      2       3     4
> ```
>
> 1 程式名（找誰做）／2 子指令（做什麼）／3 選項（附加條件）／4 值（選項要的資料）
>
> > 每一個指令都是這四種的組合。**看懂這個結構，就看得懂全部指令。**
> > 順便解釋你們畫面上那行：`npm install -g netlify-cli` ——
> > npm 商店 → install 安裝 → `-g` 是「裝到整台電腦都能用」→ 後面是要裝的東西的名字。

**這段可以隨時中斷。** 一有人喊「跑完了」就先處理他，剩下的內容不必講完 ——
完整版在 `cli-explained.md` 裡，散會時請他們自己看。

### 00:14–00:18　開終端機（右鍵法）

安裝好的視窗**關掉**（新工具要重開視窗才找得到）。

請大家：

1. 桌面按右鍵 → 新增 → 資料夾 → 命名 `my-first-page`
2. **雙擊進去**（裡面是空的）
3. 在**空白處按右鍵**：

| 系統 | 選這個 |
|---|---|
| Windows 11 | 「**在終端中開啟**」 |
| Windows 10 | **Shift + 右鍵** → 「在此處開啟 PowerShell 視窗」 |
| 都找不到 | 檔案總管**網址欄**，路徑刪掉打 `powershell` 按 Enter |

**這裡要投影你事先準備的兩張右鍵選單截圖。** 這是本場最容易卡的一步。

**講者一定要強調的一句：**

> **不要從開始選單找 PowerShell。** 那樣打開會在錯誤的位置，你會迷路。
> 一定要「先用滑鼠走到資料夾，再在裡面右鍵開」。
> 這招讓你**永遠不需要學 `cd` 這個指令**，明天正課也用同一招。

**過關訊號**：請大家確認黑窗左邊那串**結尾是 `my-first-page`**，然後在聊天室打「到了」。

不對的人：**關掉視窗重來一次**，不要試著用指令修。

### 00:18–00:22　git config（順便練右鍵貼上）

把下面兩行貼到共用文件／聊天室，請大家複製：

```powershell
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"
```

**講者示範順序**（一定要照這個順序，不然會亂）：

1. 先在自己畫面上把 `Your Name` 改成自己的名字、email 改成自己的
2. 全選、複製
3. 切到黑窗，**按滑鼠右鍵**
4. 按 Enter
5. **指出畫面什麼都沒顯示** —— 「成功的時候它就是不講話。這在終端機裡很常見。」

> 提醒：email 請用**註冊 GitHub 的那一個**。

**驗證**（貼這行請大家執行）：

```powershell
git config --global user.name
```

畫面應該吐出他們自己的名字。

**這是全場第一次「電腦回應了我設定的東西」，值得停 10 秒讓他們感受一下。**

### 00:22–00:27　gh auth login ＋ netlify login

> **這 5 分鐘是全場最容易卡的地方。** 因為它有互動選單、有 8 碼、要切到瀏覽器。
> 講者一定要**分享畫面、自己同步做一次**，不要只用嘴巴講。

**先做 GitHub：**

```powershell
gh auth login
```

**投影這張表，逐題帶。用上下方向鍵選、Enter 確認：**

| 它問什麼 | 選 |
|---|---|
| What account do you want to log into? | `GitHub.com` |
| What is your preferred protocol? | `HTTPS` |
| Authenticate Git with your GitHub credentials? | `Y` |
| How would you like to authenticate? | `Login with a web browser` |

接著畫面會顯示一組 **8 碼**，像 `A1B2-C3D4`。

**講者話術（這段照著唸）：**

> 現在畫面上有一組 8 個字的代碼。**先把它抄下來或記住。**
> 然後按 Enter，瀏覽器會自己打開。
> 把那組代碼貼進去，按 Continue，再按 Authorize。
> 回到黑窗，應該會看到一個綠色勾勾和你的帳號名稱。

**再做 Netlify：**

```powershell
netlify login
```

> 這個比較簡單，瀏覽器跳出來按 **Authorize** 就好。
> 但它會等 10–30 秒才有反應 —— **游標在閃就是在做事，不要一直按 Enter。**

**巡場重點**：這一段卡住的人會最多。處理順序是「**先讓已完成的人幫旁邊的人**」，你處理剩下的。

### 00:27–00:30　收尾：跑 check.bat 並回報

請大家回到解壓縮的那個資料夾，**雙擊 `check.bat`**，等約 1 分鐘。

**投影這張判讀表：**

| 你看到 | 意思 | 做什麼 |
|---|---|---|
| 綠色 **全部通過** | 完成了 | **截圖上傳到回報表單**，你自由了 |
| 紅色 `[缺少]` | 有東西沒好 | 照它寫的那行指令做，再雙擊一次 |
| 黃色 `[逾時]` | **不算失敗** | 忽略它 |
| 第 5 節提到 OneDrive | 你的桌面被同步 | **明天請把資料夾建在它指定的位置**，不要建在桌面 |

**最後宣布三件事：**

> 1. 沒跑出「全部通過」的人，**現在就在表單上寫你卡在哪一步**，我今天晚上一個一個回你。
> 2. 這場有錄影，等一下貼連結。沒跟上的段落自己回看。
> 3. 明天正課請帶：筆電、**手機**、印好的終端機生存卡。

## 沒裝成功的人怎麼辦

**不要為了一兩個人延長全場。** 照這個順序處理：

| 順序 | 做法 |
|---|---|
| 1 | 散會後開 **15 分鐘一對一**（線上，請他分享畫面），通常一次就解決 |
| 2 | 仍不行 → 請他**明天帶個人筆電**，重跑一次 `install.bat` |
| 3 | 還是不行 → **正課當天配一位已完成的同學，兩人共用一台筆電**，全程一起做 |
| 4 | 超過三分之一裝不起來 → **正課直接改走純瀏覽器路線**（見主教案的 Plan B） |

**判斷要不要把某人轉去純瀏覽器路線：**

- 公司／醫院電腦擋安裝，且他不願意帶個人筆電 → **轉**
- 沒有 `winget`，且不願意手動下載三個安裝檔 → **轉**
- 一對一處理過兩次仍失敗 → **轉**

轉過去不是降級。純瀏覽器路線的教學重點（改 → 存檔點 → 自動上線 → 可回復）**完全保留**，只是換操作介面。

## 這場和正課的關係

正課的**第 0 段（終端機求生，11 分鐘）**和這場有意重疊。

| | 這場（T-1） | 正課第 0 段 |
|---|---|---|
| 有來的人 | 第一次接觸終端機 | **複習**，速度可以加快 |
| 沒來的人 | — | **第一次接觸**，必須完整講 |

**所以第 0 段不能砍**，即使全員都參加了安裝場也一樣 —— 隔一天就會忘記怎麼開黑窗。

但如果出席率高，第 0 段可以壓到 8 分鐘，把省下的 3 分鐘給里程碑 4。
